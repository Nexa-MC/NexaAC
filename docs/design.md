# NexaAC 设计

SO 提供完整服务侧防护，不要求客户端；SC 在 SO 上增加游戏内协作、用户态保护、可用的平台证明与可选内核辅助。客户端不替代服务端校验。NexaAC 可独立部署；NexaSM 提供安装配置更新、证据与审计；使用 NexaCL 不证明无作弊。

## 模块与目录

src/admission：入口准入，按连接、解析、认证、后端连接、玩家初始化阶段设置预算，防绕过入口直连；不承诺抵消已打满的带宽。
src/disclosure：按遮挡、距离、玩法裁剪敏感实体、矿物与关联消息；视口仅作辅助并保留提前量，维护正常同步。
src/integrity：协议管线校验、过滤、重写、每客户端同步状态；服务端权威移动攻击交互规则，显式适配模组。
src/automation：连接与跨时间行为分析；异常不等于确定 AI，不保证识别所有 AI。
src/evidence：有效性、会话关联、去重、窗口、证据保存与复核。
src/enforcement：策略决定、本地执行与审计。
src/edge、src/server：代理与游戏 JVM 集成。
src/client-host：GameBridge、PlatformAttestation、受限 KernelBridge。
src/contracts：版本化协议契约。
distributions/so、sc：能力组合，共享服务实现。

## SC 信任边界

ClientPolicy 与 KernelPolicy 独立支持 Disabled / Optional / Required。默认不强制驱动，不另设 Kernel 产品。
拒装、不支持、故障、证据过期仅是准入或可用性结果，不能直接记作弊。
先实现能力协商、挑战、证据验证、准入会话绑定；平台或内核能力依据真实缺口增加。
客户端声明、驱动加载与签名不证明无作弊；检查覆盖范围、时效、会话关联。
内核仅提供必要最小观测保护；XSR、协议解析、模型与处罚留在用户态或服务侧。
服主仅选预定义检查项，不允许任意扫描、读内存、脚本或驱动代码下发，SM／CL 插件不能绕过。

## EnforcementPreset

| 档位 | 取向 |
| --- | --- |
| Ultimate 极限 | 接受较高误罚风险，最低有效怀疑门槛即可快速处置，不保证零漏判 |
| Extreme 极严 | 短确认窗口，快速限制、踢出或升级 |
| High 严格 | 对持续异常、重复违规、多信号积极处置 |
| Medium 标准 | 默认；综合证据、持续性、不确定性 |
| Low 宽松 | 记录提醒纠正优先，充分证据才升级 |
| Quiet 静默 | 行为处罚以观察复核为主，保留基础保护 |

防护能力、判罚强度、处罚权限相互独立。自动永久封禁单独授权，Ultimate 不隐式开启。
档位只调整触发门槛、窗口、容忍、警告与升级速度，不改变预算、权限和协议安全限制。
全部档位要求有效证据；未知模组、无效数据、未适配检测器不因高档位成为违规证据；实验 Anti-AI 可独立观察。

## 策略闭环

不可变 ProtectionProfileRevision 绑定客户端、内核、档位、检测器、披露、故障与隐私范围。Network 默认，Workload 覆盖；对局默认固定有效修订。保存不等于生效，以实际回报确认。
观察 → 有效性与去重 → 发现 → 证据窗口 → 策略决定 → 本地执行 → 审计复核。
基础保护、准入限制、行为处罚分别记录。处罚保留策略、检测器、规则版本、证据引用、作用域、期限及复核结果；处罚不等于确认作弊，不能直接作为训练标签。
